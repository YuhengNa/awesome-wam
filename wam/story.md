# WAM Project Story

## 项目缘起

### 背景：从 VLA 到 WAM

Vision-Language-Action (VLA) 模型是当前机器人基础模型的主流范式——用视觉语言大模型理解场景和指令，直接输出机器人动作。StarVLA 已经在这个方向上建立了极具影响力的模块化框架，支持四种动作解码范式（FAST/OFT/PI/GR00T）的公平对比。

然而，VLA 的骨干（VLM）学到的是**语言对齐的特征**，缺乏对物理世界动力学的显式建模。越来越多的研究开始探索 **World Action Model (WAM)**——将世界模型（视频生成/动力学预测）与动作预测结合，让机器人策略具备对物理世界的深层理解。

### 问题：WAM 设计空间碎片化

WAM 领域正处于"百花齐放但缺乏统一框架"的阶段。多篇重要工作从不同角度探索了 WAM 的设计选择，但彼此之间无法直接对比。

## 关键论文与洞见

### 1. Fast-WAM — 推理时不需要想象未来

**论文：** *Fast-WAM: Do World Action Models Need Test-time Future Imagination?*
**作者：** 袁天元、董子彬、刘一成、赵航（清华大学 & Galaxea AI）

**核心发现：** WAM 中视频建模的价值主要来自**训练阶段**（帮助模型学到物理先验），而非推理阶段的未来想象。去掉推理时的视频生成，性能仅下降 0-2%；去掉训练时的视频联合训练，性能下降 4-8%，真实世界任务甚至崩溃到 10%。

**架构：** 基于 Wan2.2-5B 视频 DiT 的 Mixture-of-Transformer (MoT)，通过注意力掩码实现动作分支与视频分支的解耦。推理时完全移除视频分支，延迟从 810ms 降到 190ms（4倍加速）。

**对本项目的启发：**
- 训练/推理时的视频生成是可以独立配置的
- 注意力拓扑（联合/因果/解耦）是 WAM 的关键设计维度
- 不同拓扑需要不同的训练时 attention mask，这不仅是推理策略的差异

### 2. LDA-1B — 结构化潜空间 + 数据质量分级

**论文：** *LDA-1B: Scaling Latent Dynamics Action Model via Universal Embodied Data Ingestion*
**作者：** Jiangran Lyu 等 23 人

**核心发现：** 在 DINO 潜空间（而非 VAE 潜空间）做动力学建模，效果从 20.0% 飙升到 55.4%。同时通过按数据质量分配学习角色（高质量→全目标，低质量→仅动力学，无动作→仅视觉预测），让低质量数据也能贡献价值，性能提升 10%。

**架构：** Multi-Modal Diffusion Transformer (MM-DiT)，1B 参数，基于 EI-30k 数据集（30,000+ 小时异质具身数据）。

**对本项目的启发：**
- 表征空间的选择（VAE vs DINO vs 多模态）对性能影响巨大
- 数据利用策略（质量分级）是 WAM 独有的设计维度
- 不是所有数据都需要用于动作学习，但都可以贡献物理先验

### 3. UnityVideo — 多模态统一生成

**论文：** *UnityVideo: Unified Multi-Modal Multi-Task Learning for Enhancing World-Aware Video Generation*
**作者：** Jiehui Huang 等（腾讯 & 香港中文大学 贾佳亚组）

**核心发现：** 在一个统一的视频扩散 Transformer 中同时处理 RGB 视频和五种结构模态（分割/深度/光流/骨骼/DensePose），多模态多任务互相增益，视频生成质量超越专用模型。

**对本项目的启发：**
- WAM 生成的内容不局限于 RGB 视频，可以是多种结构模态
- 所有模态可以统一编码到 VAE latent 空间处理
- 动态加噪策略可以灵活路由不同任务

### 4. StarVLA WM4A 模块 — 现有基础

**来源：** StarVLA starVLA_dev 分支 `docs/WM4A.md`

**做的事情：** 将预训练视频 DiT（Cosmos-Predict2、Wan2.2）作为冻结的视觉编码器，接上动作头（OFT/GR00T/PI）预测动作。本质上是用世界模型的物理对齐特征替代 VLM 的语言对齐特征。

**局限：** DiT 骨干完全冻结，无视频生成分支，无联合训练，无注意力拓扑配置，无数据质量分级。只覆盖了 WAM 设计空间中的一个极简点。

## WAM 设计空间

从上述论文中，我们提炼出 WAM 的四个核心设计维度：

### 维度一：表征空间（World Encoder 生成什么）

| 选择 | 特点 | 代表工作 |
|------|------|---------|
| VAE latent | 保留外观信息，可解码回像素 | Fast-WAM |
| DINO latent | 结构化语义特征，过滤外观噪声 | LDA-1B |
| 多模态结构 | 深度/光流/分割等多种模态 | UnityVideo |

### 维度二：生成时机（训练 vs 推理）

| 选择 | 特点 | 代表工作 |
|------|------|---------|
| 训练+推理都生成 | 完整但慢 | 传统 imagine-then-execute |
| 仅训练时生成 | 训练时塑造表征，推理时跳过 | Fast-WAM |
| 都不生成（仅编码器） | 最简，但无视频训练目标 | WM4A |

### 维度三：信息流拓扑（注意力掩码）

| 选择 | 动作能否看到未来视频 | 代表工作 |
|------|---------------------|---------|
| 联合（Joint） | 双向可见 | Fast-WAM-Joint / GR00T |
| 因果（Causal） | 动作条件化于未来视频 | Fast-WAM-IDM |
| 解耦（Decoupled） | 不可见，仅共享骨干 | Fast-WAM |

### 维度四：数据利用策略

| 选择 | 特点 | 代表工作 |
|------|------|---------|
| 统一使用 | 所有数据同等对待 | 传统 BC |
| 质量分级 | 按数据质量分配不同学习目标 | LDA-1B |

### 组合设计空间

```
WAM 设计空间 = 表征空间 × 生成时机 × 信息流拓扑 × 数据利用策略
```

目前没有任何框架能系统覆盖这个设计空间并支持公平对比。

## 项目定位

### 我们是什么

一个模块化的 World Action Model 研究框架，专注于 WAM 设计空间的系统探索。

### 我们不是什么

- 不是 StarVLA 的 feature 或插件
- 不是 OpenWorldLib（偏视频/3D 生成，不聚焦机器人动作）
- 不是又一个 WAM 方法论文的开源复现

### 与 StarVLA 的关系

**互补，不是扩展。**

| | StarVLA | 本项目 |
|---|---|---|
| 核心问题 | 动作解码范式怎么选？ | 世界模型怎么设计？ |
| 核心模块 | Action Decoder（FAST/OFT/PI/GR00T） | World Branch（表征/生成时机/拓扑/数据策略） |
| 骨干 | VLM（Qwen3-VL） | 视频 DiT（Wan2.2/Cosmos 等） |
| DiT 状态 | 冻结（仅 WM4A 模块） | 可训练，支持联合优化 |

数据格式和评测体系与 StarVLA 兼容，方便社区交叉对比。

### 技术起点

基于 StarVLA starVLA_dev 分支的 WM4A 模块 fork，保留其基础设施（数据加载、评测、训练工具链），围绕 World Branch 重新设计核心抽象层。
